Let's go ahead and set up minikube. In this section we are only going to install the basic part of minikube without the 
extra configuration needed for a better local development experience. That work will be covered in later sections.

Minikube has extensions to enable some of the functionality we need. We are going to turn them on when we spin up our 
"cluster". 

The default name the minikube CLI will give to our cluster is "minikube". I typically find the default names from 
minikube, like docker, to be unhelpful. I general give my containers and clusters names that are specific to the project 
I am working on. To give the cluster a specific name we use the -p flag (for profile) along with the name.
If you are fine with minikube as your cluster name you can drop the flag.

To start our first cluster:
```shell
    minikube start -p localdev
```

This will create a minikube cluster using your machines container engine. You should see output that looks like this:

![minikube start](images/2.1.minikube.start.png)

If you execute the following command you should see the status of your Minikube cluster:
```shell
minikube profile list
```

Your output should look like:

![minikube profile output](images/2.2.minikube.profile.png)

This output shows the profile name, that is using containers for its "VM", the IP of the cluster, the port for the 
Kubernetes API server, the version, whether it is running, how many nodes, and that is has been set to be the
active context for our kubectl config.
